# Git 提交（中文 + Conventional Commits）

## 必须遵守

1. **类型前缀**：使用小写英文类型，与 [Conventional Commits](https://www.conventionalcommits.org/) / Angular 规范一致。
2. **说明语言**：**第一行标题与正文一律使用中文**（专有名词、文件名、API 路径可保留英文）。
3. **执行提交**：用户明确要求提交时，在仓库内执行 `git commit`，消息按本节格式编写；勿用全英文标题敷衍用户的中文习惯。

## 第一行格式

```
<类型>[可选作用域]: <中文简短描述>
```

- **类型**（常用）：`feat` 新功能、`fix` 修复、`docs` 文档、`style` 格式/分号等不影响逻辑的样式、`refactor` 重构、`perf` 性能、`test` 测试、`chore` 杂项/工具、`build` 构建、`ci` 持续集成、`revert` 回滚。
- **作用域**（可选）：括号内用简短中文或模块名，如 `feat(配置页):`、`fix(扫描):`、`refactor(backend):`。与代码库目录或模块一致即可。
- **描述**：动词开头、**50 字内为宜**，句末一般不加句号；用中文清晰说明「做了什么」。

### 破坏性变更

- 在类型后加 `!`：`feat(api)!: 移除忽略分支相关接口`
- 或在正文末段写：`BREAKING CHANGE: <中文说明迁移方式或影响>`

## 正文（可选）

需要时用空行隔开，用中文分条或短段落说明：

- 动机或背景（一两句即可）
- 主要改动点（列表）
- 关联 issue / 任务编号（若有）：`Closes #123`

避免堆砌无意义套话；每条信息应对审查者有用。

## 示例

**新功能：**

```
feat(配置管理): 支持批量删除仓库

- 表格增加多选与批量删除确认
- 调用后端 batch-delete 接口
```

**修复：**

```
fix(统计): 修正跨日时间边界下提交漏计问题

扫描结束时间改为闭区间，与需求文档 2.7 节一致
```

**重构 / 移除能力：**

```
refactor!: 端到端移除忽略分支能力

- Prisma 删除 IgnoredBranch 表及迁移
- 去掉 config 相关路由与前端 IgnoredBranchesManager
- 更新 README 与需求文档说明
```

**文档：**

```
docs(需求): 同步全图扫描与 merge commit 口径说明
```

**杂项：**

```
chore: 升级开发依赖并锁定 pnpm 版本
```

## 反例（不要这样写）

- `feat: add login` — 描述应为中文。
- `更新了代码` — 缺少类型前缀，信息模糊。
- `fix bug` — 无作用域可接受，但应用中文写清修复对象与现象。

## 与用户协作

- 若变更混杂多种类型，可拆成多次提交；单次提交优先单一意图。
- 用户指定「和上次一样」「简短点」时，在符合类型的前提下压缩正文，**标题仍保持「类型 + 中文描述」**。
