# 数据总览 V2 开发计划

## 1. 目标

在不丢失 Merge Commit 和历史数据的前提下，统一统计口径，重构数据总览的信息架构，并消除加班筛选、时区、配置联动和仓库删除提示中的不一致。

## 2. 实施阶段

### 阶段一：数据口径与接口

1. 将按日分组统一为 `Asia/Shanghai` 自然日。
2. 将提交查询的布尔参数 `isOvertime` 升级为枚举参数 `overtimeMode`：
   - `all`
   - `overtime_days`
   - `overtime_commits`
   - `non_overtime_days`
3. 保留旧 `isOvertime` 参数的兼容解析：`true` 映射为 `overtime_days`，`false` 映射为 `non_overtime_days`。
4. 总览接口返回：
   - 总提交数
   - 活跃天数
   - 加班天数
   - 加班提交数
   - 仓库活动分布
   - 加班天数最多月份
   - 当前数据指标配置
5. 仓库分布返回提交数、占比计算所需总数、文件变化数、新增和删除行数。

### 阶段二：数据总览前端

1. 重写 `/data-overview`，移除 Top1 仓库、加班仓库和普通月份峰值卡片。
2. 新增四个核心指标卡片及对应下钻。
3. 新增仓库活动分布横向进度条，支持仓库下钻。
4. 保留并强化“加班天数最多月份”，补充活跃天数和加班日占比。
5. 日期预设改为动态当前年度，不再写死 2025/2026。

### 阶段三：Git 数据看板

1. 筛选状态从 `isOvertime?: boolean` 调整为 `overtimeMode`。
2. 下拉选项改为“加班日期 / 加班提交 / 非加班日期”。
3. 汇总统计根据过滤后的日期组计算，确保与列表口径一致。
4. 工作状态标签、颜色和 Tooltip 使用接口返回的用户配置。

### 阶段四：删除安全

1. 修正批量删除提示，明确历史提交会永久删除。
2. 单仓库删除确认同样补充历史数据影响。
3. 保留仓库启用/停用能力，作为不删除历史数据的推荐操作。

## 3. 兼容策略

- 数据库结构不变，不需要迁移。
- 现有 Commit 全部保留，Merge Commit 不做过滤或重写。
- 旧客户端仍可使用 `isOvertime`，新客户端统一使用 `overtimeMode`。
- 总览接口属于当前项目内部接口，前后端同步升级响应结构。

## 4. 测试计划

### 后端

- 验证上海时间日期边界：00:00、07:59、08:00、18:59、19:00。
- 验证一个加班日包含多条加班提交时的去重统计。
- 验证四种 `overtimeMode` 返回范围。
- 验证仓库分布汇总与总提交数一致。
- 验证加班最忙月份使用去重日期数。

### 前端

- TypeScript 构建通过。
- 四个指标下钻标题和结果正确。
- 仓库分布在长仓库名和移动端宽度下不溢出。
- 配置化标签、颜色和 Tooltip 正确展示。
- 删除确认文案与后端行为一致。

### 回归

- 手动扫描和定时扫描不受影响。
- 仓库、作者和日期筛选仍然有效。
- Merge Commit 的文件变化和代码变化仍正常展示。
- 默认近一个月查询在现有数据量下正常返回。
