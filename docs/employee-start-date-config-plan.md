# 入职时间配置与数据看板联动方案

## 1. 需求范围

为配置管理增加一个全局“入职时间”字段，并将其用于数据看板：

1. 配置管理的数据指标配置中可以查看、编辑和保存入职时间。
2. 数据看板日期组件的“全部时间”快捷范围，起始日期使用入职时间，结束日期使用当前日期。
3. “工作强度占比”卡片标题右侧增加入职时间和在职天数。
4. 在职天数按上海时区的自然日计算，入职当天计为 1 天。

本次只配置一个全局入职时间，不按仓库或作者拆分。

## 2. 技术方案

### 2.1 数据存储

复用现有 `DataMetricsConfig` 单例配置，在数据库增加可空的 `hire_date` BIGINT 字段，单位为毫秒时间戳。可空是为了兼容已有数据库；未配置时前端显示“未配置”，数据看板“全部时间”回退为最早已入库提交日期。

### 2.2 后端接口

`GET /api/v1/config/data-metrics` 返回 `hireDate: number | null`。

`PUT /api/v1/config/data-metrics` 接收 `hireDate: number | null`，并校验：

- 必须是合法的毫秒时间戳或 null；
- 非 null 时不能晚于当前时间；
- 保留已有阈值、加班时间、标签和颜色校验。

数据看板接口 `/api/v1/statistics/overview` 继续复用数据指标配置，并在 `metricsConfig` 中返回 `hireDate`，避免看板产生第二套配置来源。

### 2.3 前端行为

- 配置页使用日期选择器编辑入职时间，显示格式为 `YYYY-MM-DD`。
- 日期看板初始化时同时加载数据指标配置；“全部时间”起点优先取 `hireDate`，没有入职时间时使用提交日期范围的最早日期。
- 工作强度占比卡片标题右侧显示：`入职时间：YYYY-MM-DD`、`在职天数：N 天`。
- 在职天数使用上海自然日差值加 1：

  `在职天数 = 当前上海日期 - 入职上海日期 + 1`

- 未配置时展示 `入职时间：未配置`、`在职天数：-`。

## 3. 验收标准

1. 配置页可新增、修改、刷新回显入职时间。
2. 已有数据库配置升级后仍可正常读取和保存。
3. 数据看板“全部时间”的开始日期等于入职时间当天，结束日期为当前日期。
4. 未配置入职时间时，“全部时间”回退到最早提交日期，不影响已有用户。
5. 工作强度占比卡片标题右侧展示入职时间和在职天数。
6. 入职当天在职天数为 1，次日为 2，按上海时区自然日计算。
7. 未来日期无法保存。
8. 完成后执行后端和前端构建、差异检查；不执行浏览器验证。
