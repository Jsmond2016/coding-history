# 数据总览 V2 需求文档

## 1. 文档信息

- 版本：v2.0
- 日期：2026-07-14
- 页面：`/data-overview`、`/git-statistics`
- 产品定位：帮助开发者回顾指定周期内的代码活动、业务投入和加班情况，并提供可追溯的提交明细。

## 2. 产品原则

1. 所有 Commit 都是开发活动记录，Merge Commit 也必须纳入提交、文件变化和代码变化统计。
2. 提交数、文件变化数和代码行变化数只描述活动规模，不直接等价于开发耗时或绩效。
3. Merge 的实际耗时由开发者结合提交信息、文件变化数和代码变化量自主判断，系统不自动折算工时。
4. 加班以用户配置的加班时间阈值为准。当前默认阈值为 19:00，提交时间达到阈值即为加班提交。
5. 同一上海自然日内存在一条或多条加班提交，该日只计为 1 个加班日。
6. 所有日期分组、月份聚合、加班判断和时间展示统一使用 `Asia/Shanghai`。

## 3. 核心用户问题

数据总览需要优先回答：

1. 当前周期有多少代码活动，分布在多少工作日？
2. 代码活动主要集中在哪些仓库，各仓库占比如何？
3. 有多少天发生了加班，加班集中在哪个月？
4. 加班当天处理了哪些业务、有哪些提交、发生在什么时间？
5. 当前数据是否已经完成同步，是否存在覆盖缺失？

## 4. 数据总览页面

### 4.1 筛选条件

- 日期范围，默认近一个月；预设与 Git 数据看板一致，包含最近一周、最近一个月、最近三个月、最近半年、最近一年和全部时间。
- 仓库，多选，默认全部仓库。
- 作者，多选，默认全部作者。
- 查询按钮。
- “全部时间”从最早已入库提交日期起算，到今天结束。

### 4.2 核心指标

首行展示以下指标：

| 指标 | 口径 | 下钻行为 |
| --- | --- | --- |
| 提交总数 | 筛选范围内全部 Commit 数，包含 Merge 和 Release | 展示当前范围全部提交 |
| 活跃天数 | 至少有一条提交的上海自然日数量 | 展示全部活跃日期 |
| 加班天数 | 至少有一条加班提交的上海自然日数量 | 展示加班日期及当天全部提交 |
| 加班提交数 | 达到加班阈值的 Commit 数 | 仅展示加班时间段内的提交 |

加班天数卡片同时展示 `加班天数 / 活跃天数` 占比。加班提交数用于了解加班时段的提交密度，但不得替代加班天数。

### 4.3 仓库活动分布

- 展示筛选范围内所有活跃仓库，不只展示第一名。
- 每个仓库展示：仓库名、提交数、提交占比、文件变化数、代码新增/删除行数。
- 使用横向进度条表达提交占比，按提交数降序排列。
- 点击仓库后展示该仓库在当前筛选范围内的全部提交。
- 仓库活动项悬停时显示可点击鼠标样式，并提示“点击可筛选该仓库的提交历史”。
- 区域顶部展示活跃仓库总数。

### 4.4 加班最忙月份

- 保留“加班天数最多的月份”。
- 使用紧凑卡片展示，避免与仓库活动列表等高造成大面积留白。
- 统计口径为每个月的加班自然日数量，不是加班提交数量。
- 展示月份、加班天数、该月活跃天数和加班日占比。
- 点击后展示该月所有加班日期，并携带每天的全部提交。
- 若筛选范围内无加班日期，展示空状态。

### 4.5 活动占比

- 在仓库活动分布上方展示两个并排的实心饼图。
- 仓库提交次数占比饼图以当前筛选范围的提交总数为分母。
- 工作强度占比饼图以当前筛选范围的活跃天数为分母。
- 工作强度使用配置化阈值划分为轻松、正常、忙碌、疯狂四个互斥区间，合计等于活跃天数。
- 两个饼图均展示图例、数量和百分比；无数据时展示空状态。
- 点击仓库占比扇区可下钻对应仓库提交；点击工作强度扇区可下钻对应强度日期的提交。

### 4.6 加班业务明细

- 移除“加班最多仓库”，仓库不是加班原因，不作为核心结论。
- 加班明细按日期展示当天全部提交，以保留完整工作上下文。
- 每个日期需突出显示：加班提交时间、提交信息、仓库、文件变化数、新增/删除行数。
- 提交信息是识别业务内容的主要依据，后续可基于 Conventional Commit 的 scope 聚合业务主题。

### 4.7 下钻区域

- 默认不加载大体量明细，用户点击指标或仓库后再加载。
- 标题必须明确当前下钻条件。
- “加班日期”下钻返回当天全部提交；“加班提交”下钻只返回加班时段提交。

## 5. Git 数据看板筛选

原“加班”筛选拆分为四个互斥状态：

| 选项 | 返回内容 |
| --- | --- |
| 全部 | 返回所有有提交的日期及全部提交 |
| 加班日期 | 只返回存在加班提交的日期，每天返回全部提交 |
| 加班提交 | 只返回达到加班阈值的提交，并按日期分组 |
| 非加班日期 | 只返回完全没有加班提交的日期，每天返回全部提交 |

统计卡片和趋势图必须与当前筛选口径一致，不得出现列表已筛选但汇总仍是全量数据的情况。

## 6. 指标配置联动

- 工作状态阈值、加班时间、标签文本、标签颜色均读取数据指标配置。
- 页面 Tooltip 必须根据当前阈值动态生成，不得写死 `6/10/15/20/19`。
- 修改配置后重新查询即可生效，无需重启服务。

## 7. 仓库删除安全

- “停用仓库”用于停止后续扫描，不删除历史提交。
- “永久删除仓库”会删除仓库配置、作者配置及其全部历史提交。
- 永久删除前必须明确展示会删除历史数据，使用危险操作样式并二次确认。
- 禁止出现“保留提交记录”但后端实际删除记录的错误提示。

## 8. 验收标准

1. 上海时间凌晨提交不会被分组到前一日。
2. 同一天有多条 19:00 后提交时，加班天数只增加 1，加班提交数按实际条数增加。
3. Merge Commit 出现在总数、仓库分布和明细中，文件变化数据正常展示。
4. 仓库提交占比之和在允许的四舍五入误差内等于 100%。
5. 加班最忙月份按去重后的加班日期排序。
6. “加班日期”展示当天全部提交，“加班提交”只展示加班提交。
7. 修改指标标签、颜色、阈值和加班时间后，统计页展示与配置一致。
8. 永久删除仓库前的提示与实际删除行为完全一致。
