# Git 数据工作台 V2 需求文档

## 1. 产品定位

- 路由：`/git-statistics`
- 页面名称：提交记录工作台
- 核心目标：按条件定位提交，观察代码活动趋势，并复盘某一天的完整开发过程。
- 与数据总览的边界：`/data-overview` 负责周期概览和分布，工作台负责检索、逐日浏览和提交明细。

## 2. 核心使用场景

1. 按日期、仓库、作者定位一段时间内的提交。
2. 搜索 Commit Hash、提交信息或业务 scope。
3. 分别查看加班日期、加班提交和非加班日期。
4. 查看某日从早到晚的跨仓库开发时间线。
5. 判断一段时间的工作强度和加班情况。
6. 在明确仓库与日期范围后同步 Git 数据。
7. 将当前筛选结果通过 URL 收藏或分享，并在刷新后恢复。

## 3. 页面结构

### 3.1 页面标题区

- 展示“提交记录工作台”和简短副标题。
- 展示最近一次查询完成时间。
- 提供独立的“同步数据”按钮，不与查询筛选混为一个操作。

### 3.2 查询筛选区

基础筛选：

- 日期范围，默认近 1 个月，支持任意时间范围；预设包含从最早已入库提交日期到今天的“全部时间”。
- 仓库，多选。
- 作者，多选。
- 加班模式：全部提交、加班日期、加班提交、非加班日期。

提交检索：

- 关键字：匹配完整 Commit Hash、短 Hash、提交信息、作者名、作者邮箱和仓库名。
- 提交类型，多选：Feature、Fix、Refactor、Docs、Merge、Release、Chore、Other。

交互要求：

- 修改筛选条件后，明确显示“筛选条件尚未应用”。
- 点击“应用筛选”后才更新结果、URL 和已应用条件。
- 点击“重置”恢复默认条件并立即查询。
- URL 查询参数可完整恢复已应用筛选。

### 3.3 同步数据

- 点击“同步数据”打开确认弹窗。
- 弹窗明确展示仓库范围和日期范围。
- 已选择仓库时，同步所选仓库；未选择时，使用主任务仓库集合。
- 日期范围支持 3 天、1 周、2 周、1 月、3 月、6 月和当前筛选日期。
- 用户确认后才开始同步。
- 同步结束后自动刷新当前已应用查询。

### 3.4 提交活动汇总

汇总指标遵循当前已应用的提交筛选：

- 提交总数。
- 累计新增代码行数。
- 累计删除代码行数。
- 累计文件变更数。

上述指标包含 Merge Commit；它们用于描述活动规模，不直接换算工时。

### 3.5 工作状态

- 工作状态始终基于日期、仓库、作者范围内的当天完整提交计算。
- 关键字、提交类型和“加班提交”不得改变当天工作状态。
- 工作强度按提交次数重新划分为互斥区间：轻松、正常、忙碌、疯狂。
- 4 个区间之和必须等于活跃天数。
- 加班天数作为独立维度展示，不与工作强度重复相加。
- 阈值、加班时间、标签和颜色读取用户指标配置。

### 3.6 提交趋势

- 趋势遵循当前已应用的提交筛选。
- 日期轴必须补齐无提交日期并显示 0，不能跨空白日期直接连接。
- 使用非平滑折线，避免离散提交次数产生虚假中间值。
- X 轴使用完整日期作为唯一键，展示时可缩写为 `MM-DD`。
- 标题需反映筛选语义，例如“加班提交趋势”。

### 3.7 日期与提交明细

采用左右分栏：

- 左侧日期列表：日期、提交数、加班数、发版状态。
- 右侧提交时间线：展示当前选中日期的完整内容。
- 日期切换不展开多个折叠面板，避免页面滚动与内部滚动嵌套。
- 时间线统一从早到晚。
- 提交展示仓库、作者、Hash、时间、分支、提交信息、文件变更、代码增删和加班状态。
- Hash 支持复制。
- 右侧可按仓库切换“全部 / 单仓库”，但不重复创建日期级折叠面板。

## 4. 空状态与错误状态

- 查询无结果时说明当前筛选没有匹配提交，并提供重置筛选操作。
- 查询失败时页面内展示错误和“重新查询”，不能只显示全局 Toast。
- 仓库或作者列表加载失败时展示明确提示，不能静默显示空下拉框。

## 5. 响应式与可访问性

- 筛选控件具有可访问名称。
- 桌面端使用左右分栏；窄屏改为日期列表在上、明细在下。
- 指标卡片在窄屏自动换行，不使用固定 `span=6` 压缩文字。
- 交互元素必须支持键盘操作和可见焦点。
- 长仓库名、作者和提交信息不得撑破布局。

## 6. 验收标准

1. 修改筛选但未应用时，结果区仍明确对应旧条件，并显示待应用状态。
2. 刷新带查询参数的 URL 后可恢复相同结果。
3. “加班提交”模式只影响提交汇总和趋势，不改变完整日期工作状态。
4. 工作强度各区间互斥，合计等于活跃天数。
5. 趋势图包含筛选范围内的 0 提交日期，跨年份 Tooltip 不串数据。
6. 同步弹窗展示的仓库与日期范围和实际请求一致。
7. 默认近一个月数据只展示一个日期明细面板，不产生多层嵌套滚动。
8. Commit Hash 可复制，全部作者模式下可识别每条提交的作者。
