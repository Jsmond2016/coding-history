# 数据采集流程 V2 需求文档

## 1. 文档信息

- 版本：v2.0（待确认）
- 日期：2026-07-15
- 涉及页面：`/config`、`/tasks`、`/git-statistics`
- 本阶段目标：重构仓库、作者、扫描计划和扫描执行之间的业务流程。

## 2. 产品结论

用户真正需要管理的不是“配置”和“任务”两个技术模块，而是一条数据采集链路：

1. 添加或发现 Git 仓库。
2. 为每个仓库选择需要采集的 Git 作者。
3. 确认数据源已经可以扫描。
4. 选择立即手动扫描，或把数据源加入定时扫描计划。
5. 查看执行状态、失败原因和新增提交数。

V2 将产品对象收敛为：

| 产品对象 | 含义 |
| --- | --- |
| 数据源 | 一个 Git 仓库及其需要采集的作者集合 |
| 扫描计划 | 对一组数据源定时执行的策略 |
| 扫描执行 | 某次手动或定时扫描的运行记录 |

“手动任务”不再作为需要长期保存的产品对象。手动扫描是一项即时操作。

## 3. 当前问题

### 3.1 配置管理

1. 仓库与作者虽然有先后依赖，但当前通过表格、展开行、编辑图标和多个弹窗分散完成，缺少完成状态。
2. 手工添加仓库时只校验必填，不验证路径是否存在、是否为 Git 仓库、是否重复。
3. 扫描目录向导只能给所有仓库配置同一个作者，不能逐仓库确认或覆盖。
4. 作者邮箱只能手工输入，用户需要自行去 Git 查询准确值，输错后扫描会静默跳过。
5. `isDefault` 只影响视觉标签，不影响扫描行为，属于无效概念。
6. “异常项目”把未首次扫描、作者错误、空仓库等不同问题合并成一种状态，并把删除作为主要处理方式。
7. 备份数据库、仓库发现、异常检测、刷新、批量删除、添加仓库全部堆在同一工具栏，操作优先级混乱。

### 3.2 任务管理

1. 每个启用仓库会自动生成一条单仓库手动任务，9 个仓库当前产生了 12 条任务，并存在重复任务。
2. `GET /tasks` 会创建或删除任务，读取列表具有隐藏副作用。
3. “手动任务”与页面里的直接同步能力重复，用户不知道应该去统计页同步还是触发任务。
4. “主任务”同时承担默认仓库范围和定时调度两种职责。
5. 将任务设为主任务时，系统会自动把它改成定时任务、启用、近 3 天、工作日 9:00，超出用户操作预期。
6. 主任务可以被编辑、禁用或删除，缺少业务不变量保护。
7. 普通用户需要直接填写 Cron 表达式，但看不到自然语言含义和下次执行时间。
8. 拖拽排序、恢复默认排序、批量修改扫描范围不是核心扫描流程，却占据主要操作空间。
9. 任务触发后只提示“后台执行”，列表无法准确展示运行中、部分成功、完成时间和具体失败仓库。

## 4. 信息架构

### 4.1 `/config`：数据源与系统设置

页面名称改为“数据源管理”，使用 3 个页签：

1. 数据源：仓库、作者、准备状态、最近扫描。
2. 统计规则：工作强度、加班时间、标签和颜色。
3. 系统维护：数据库备份目录、备份计划和立即备份。

数据库备份不再出现在仓库工具栏。

### 4.2 `/tasks`：扫描计划

页面名称改为“扫描计划”，只展示定时扫描策略，不展示系统自动生成的手动任务。

页面由两部分组成：

1. 扫描计划：计划范围、执行频率、回溯窗口、启用状态。
2. 最近执行：运行状态、触发方式、开始/完成时间、仓库结果、新增提交和错误。

### 4.3 手动扫描

`/git-statistics` 和数据源页均可打开同一个“同步数据”弹窗。弹窗直接选择数据源和时间范围，不创建任务记录，只创建扫描执行记录。

## 5. 数据源管理需求

### 5.1 数据源状态

每个仓库展示一个互斥的准备状态：

| 状态 | 条件 | 推荐操作 |
| --- | --- | --- |
| 待配置作者 | 仓库有效但没有作者 | 配置作者 |
| 待首次扫描 | 仓库和作者有效，但没有扫描记录 | 立即扫描 |
| 正常 | 最近扫描成功，配置完整 | 无 |
| 扫描过期 | 超过设定时间未成功扫描 | 立即扫描或检查计划 |
| 路径异常 | 路径不存在或不是 Git 仓库 | 修改路径 |
| 作者无匹配 | 已扫描但所选作者没有匹配提交 | 重新选择作者 |
| 最近扫描失败 | 最近一次扫描存在失败 | 查看失败原因并重试 |
| 已停用 | 仓库不参与扫描 | 启用 |

禁止使用单一“异常项目”标签覆盖上述状态，健康检查不得直接引导删除。

### 5.2 新增数据源向导

统一“添加仓库”和“扫描仓库”为一个向导：

#### 第一步：选择添加方式

- 扫描目录：递归发现多个 Git 仓库。
- 输入路径：添加单个 Git 仓库。

#### 第二步：验证与选择仓库

- 验证路径存在且为 Git 仓库。
- 使用规范化真实路径识别重复仓库。
- 自动生成仓库名称和 ID，ID 收入高级设置。
- 用户勾选本次需要添加的仓库。

#### 第三步：配置作者

- 系统从每个仓库的 Git 历史中发现作者姓名、邮箱和提交数量。
- 支持选择一个公共作者应用到所有仓库。
- 支持逐仓库覆盖作者，可多选。
- 允许手工补充未发现的邮箱。
- 移除“默认作者”概念；所有选中作者参与扫描。

#### 第四步：完成方式

- 仅保存数据源。
- 保存并立即扫描。
- 保存、立即扫描并加入默认扫描计划。

提交前展示仓库数、作者覆盖情况、首次扫描范围和计划影响。

### 5.3 数据源列表

首要字段：

- 仓库名称与路径。
- 准备状态。
- 作者数量和姓名。
- 所属扫描计划。
- 最近成功扫描时间。
- 当前提交数据范围。

主操作根据状态变化：配置作者、立即扫描、查看结果。编辑、停用和永久删除进入更多菜单。

批量操作仅保留：配置公共作者、加入扫描计划、立即扫描、启用/停用。永久删除不作为常用批量操作。

## 6. 扫描计划需求

### 6.1 计划模型

扫描计划仅表示定时扫描，包含：

- 计划名称。
- 数据源范围，至少选择 1 个已启用且配置作者的数据源。
- 执行频率。
- 扫描回溯窗口。
- 启用状态。
- 是否为默认计划。

默认计划只表达“新数据源可选择加入的默认计划”和“未显式选择仓库时的建议范围”，不得自动修改其他字段。

### 6.2 执行频率

默认提供业务化预设：

- 工作日每天 09:30。
- 工作日每天 19:00。
- 每天指定时间。
- 每周指定星期和时间。
- 高级 Cron。

选择后展示自然语言摘要、`Asia/Shanghai` 时区和未来 3 次执行时间。Cron 只放在高级模式。

### 6.3 扫描回溯窗口

- 近 1 天、3 天、7 天、2 周、1 个月。
- 定时计划不允许固定的历史自定义起止日期，因为过期后会重复扫描同一段历史。
- 历史补录使用手动扫描的自定义日期范围，最大 6 个月。

### 6.4 计划列表

每个计划展示：

- 名称、启用状态、默认计划标识。
- 数据源数量和异常数量。
- 执行频率自然语言。
- 扫描窗口。
- 下次执行时间。
- 最近一次结果。

主操作：立即运行。次级操作：编辑、启用/停用、设为默认、查看历史、删除。

移除拖拽排序、恢复默认排序、批量修改扫描范围和批量触发。

## 7. 扫描执行需求

每次执行都创建独立记录：

- 触发来源：手动、定时。
- 关联计划，可为空。
- 开始时间、结束时间、持续时间。
- 状态：等待中、运行中、成功、部分成功、失败。
- 请求仓库、成功仓库、失败仓库、跳过仓库。
- 新增提交数、重复跳过数。
- 每个仓库的结果和错误原因。

手动操作提交后返回运行 ID，前端轮询该运行状态，不使用固定 2 秒刷新猜测是否完成。

同一仓库已有扫描运行时，新的执行应拒绝或排队，避免同时 `git pull` 和重复扫描。

## 8. 关键规则

1. 仓库没有作者时不能加入扫描计划，也不能发起扫描；界面直接引导配置作者。
2. 停用仓库时不删除计划，计划中显示该数据源已停用并在执行时跳过。
3. 删除仓库前展示关联计划和历史提交影响。
4. 删除默认计划前必须先指定新的默认计划，或明确进入“无默认计划”状态。
5. 设置默认计划不得修改类型、频率、窗口或启用状态。
6. 列表查询接口不得创建、修改或删除数据。
7. 所有计划和执行时间统一使用 `Asia/Shanghai`。

## 9. 验收标准

1. 新用户可在一个向导内完成仓库发现、作者选择、首次扫描和加入计划。
2. 作者可从 Git 历史选择，无需优先手输邮箱。
3. 数据源列表可以直接看出哪些仓库尚未准备好以及下一步操作。
4. `/tasks` 默认只展示定时计划，不展示每仓库自动生成的手动任务。
5. 读取任务列表不会创建或删除任何记录。
6. 设置默认计划不会改变计划的执行频率、窗口和启用状态。
7. 普通模式无需填写 Cron，并能看到未来执行时间。
8. 手动和定时扫描都有可查询的运行状态及逐仓库结果。
9. 仓库缺少作者、路径异常或被停用时，扫描前即可得到明确反馈。

## 10. 待确认决策

建议采用以下默认决策：

1. 手动扫描不再保存为任务：确认。新仓库通过一次性“首次扫描”补录近 1 个月；日常手动同步默认近 3 天，也可临时选择其他范围。两者都保存为扫描执行记录，不保存为长期任务。
2. 每仓库自动手动任务停止创建，并从主界面隐藏：确认。
3. 保留多个定时计划，允许一个默认计划：确认。
4. 新数据源首次扫描默认范围：近 1 个月。
5. 数据源加入默认计划：向导中默认勾选，但允许取消。
6. 旧手动任务先隐藏并标记为待清理，不自动删除，避免误删用户自定义配置。

以上决策已于 2026-07-15 确认，进入开发实施。
