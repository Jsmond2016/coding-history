# 长期提交报告截图需求文档

## 1. 文档信息

- 版本：v1.1（待评审）
- 日期：2026-09-16
- 涉及页面：`/git-statistics`、`/data-overview`
- 关联文档：[Git 数据工作台 V2 需求](./git-statistics-v2-requirements.md)、[数据总览 V2 需求](./data-overview-v2-requirements.md)

## 2. 背景与目标

当前提交记录工作台的筛选时间跨度被前端限制为 2 年，数据总览被接口和前端限制为 3 年。这与开发者在离职交接、工作成果回顾或展示完整职业周期时查看历史数据的需求冲突。

本需求提供“长期提交报告截图”：用户可基于已入库的全部历史提交选择任意时间范围，生成可预览、下载并通过任意聊天工具发送的图片。报告用于说明代码活动、覆盖项目和工作节奏，不用于自动推导工时、绩效或工作质量。

## 3. 范围

### 3.1 本期包含

1. 放开提交记录工作台和数据总览的展示筛选时间上限。
2. 根据当前已应用的筛选条件生成长期提交报告截图。
3. 预览、下载汇总长图，以及可选的月度明细图片包。
4. 为长时间范围提供聚合展示和分段导出，避免一次加载或绘制全部 Commit。
5. 在截图中清晰标识数据覆盖范围、生成时间、筛选条件和数据局限。

### 3.2 本期不包含

1. 超过 6 个月的手动同步需要用户二次确认，并提示可能耗时较长或失败；确认后按选择范围执行，失败时建议拆分为较短区间重试。
2. 不自动扫描尚未入库的历史记录。
3. 不生成分享链接、公开路由、报告快照表、访问统计或报告管理功能。
4. 不接入第三方公开网站、社交平台或文件存储。
5. 不将提交数、代码行数或加班记录折算为工时、绩效分数或个人能力评价。

## 4. 用户与使用场景

| 用户 | 场景 | 期望结果 |
| --- | --- | --- |
| 开发者 | 离职前回顾历年负责的仓库与代码活动 | 查看完整时间范围，不受 2/3 年限制 |
| 开发者 | 向交接人、主管或合作方展示某段经历 | 下载一张概览图，直接发送即可阅读 |
| 开发者 | 需要补充某一阶段的工作内容 | 按月导出明细图片，而非在聊天工具中发送超长单图 |
| 开发者 | 发现内容不适合外发 | 在导出前关闭仓库名、作者名或提交信息 |

## 5. 业务规则

1. “全部历史”表示当前筛选的仓库、作者范围内，数据库中最早至最新的已入库提交日期；不代表本地 Git 仓库一定已完成全历史扫描。
2. 时间范围必须满足开始日期不晚于结束日期，但不再存在 2 年或 3 年的展示上限。
3. 所有日期分组、月度聚合、加班判断和时间展示继续统一使用 `Asia/Shanghai`。
4. 默认查询范围仍为近 1 个月，避免首次进入页面加载过重；用户可主动选择“全部历史”或任意自定义范围。
5. 截图内容以生成时当前已加载的数据为准。生成后的图片是静态文件，后续扫描、删除提交或调整指标配置不会改变已下载图片。
6. 截图仅包含生成者明确选择的仓库、作者和时间范围；未选择仓库/作者时，生成前必须展示实际纳入的仓库和作者数量。
7. 默认截图不展示本地仓库绝对路径、作者邮箱、完整 Commit Hash 和原始提交信息。仓库名、作者名、短 Hash 与提交信息须由生成者逐项开启。
8. 汇总图不包含单条 Commit。明细图只在用户主动选择“包含月度明细”后生成。

## 6. 功能需求

### 6.1 放开历史筛选

#### 提交记录工作台 `/git-statistics`

- 移除日期选择器中“时间范围不能超过 2 年”的前端校验。
- URL 参数 `start`、`end` 可恢复任意合法历史范围；加载该链接时不得因跨度大而回退为默认近 1 个月。
- 新增“全部历史”快捷项。系统根据当前仓库、作者条件查询可用数据边界；无数据时禁用该快捷项并提示原因。
- 保留既有默认近 1 个月、快捷日期、筛选未应用提示和 URL 恢复行为。

#### 数据总览 `/data-overview`

- 移除前端“自定义时间周期不能超过 3 年”和接口 3 年跨度校验。
- 新增“全部历史”快捷项，并以当前作者条件下的已入库数据边界填充日期选择器。
- 原有总览、仓库分布、加班最忙月份和下钻口径保持不变。

#### 数据边界

- 新增查询能力，返回当前筛选条件下：最早提交日期、最新提交日期、提交总数、活跃仓库数及是否存在未完成首次扫描的数据源。
- 页面在“全部历史”和截图生成确认区展示数据边界与“仅统计已入库数据”提示。

### 6.2 长期提交报告截图

- 在工作台和数据总览提供“导出长期报告”入口，入口使用当前已应用的筛选条件；筛选尚未应用时按钮禁用，并提示先应用筛选。
- 入口沿用现有单日提交图片的“生成预览后确认下载”交互，新增周期报告图片生成器。
- 点击后打开配置弹窗，展示并允许调整：
  - 报告标题，必填，默认“提交记录回顾”。
  - 时间范围、仓库、作者和已入库数据边界摘要。
  - 导出内容：仅汇总（默认）或汇总加月度明细图片。
  - 内容开关：仓库名称、作者名称、短 Hash、提交信息；提交信息默认关闭。
  - 图片比例：横版 `16:9`、竖版 `9:16`；默认竖版，适合聊天工具和手机阅读。
- 配置确认后先生成概览图预览，预览中显示完整视觉内容与文件名。用户点击“确认下载”后才保存图片。
- 选择“汇总加月度明细图片”时：
  - 概览图始终生成 1 张。
  - 每个有提交的自然月生成 1 张明细图；图片按 `YYYY-MM` 命名并下载为 ZIP。
  - 单月明细超过 100 条 Commit 时，按时间顺序切分为多张，每张最多 100 条，并在图片标题标记分段序号。
- 图片生成失败时显示明确错误并支持重试，不下载不完整文件。

### 6.3 截图内容与排版

#### 概览图

概览图必须包含：

1. 报告标题、生成日期、覆盖日期和“仅统计已入库数据”说明。
2. 当前筛选摘要：仓库数量、作者数量、加班模式；用户开启时才列出仓库名或作者名。
3. 提交总数、活跃天数、活跃仓库数、新增代码行数、删除代码行数和加班天数。
4. 提交趋势：范围超过 18 个月时按月聚合；18 个月及以内按日展示并补齐无提交日期。
5. 仓库活动分布：最多展示提交数前 8 的仓库；其余合并为“其他”。未开启仓库名时使用“项目 1、项目 2”等匿名标签。
6. 页尾声明：“数据来自已入库 Git 提交记录，不代表工时、绩效或全部工作产出。”

#### 月度明细图

- 按月展示标题、月份范围、当月汇总指标及时间线。
- 每条提交展示时间、仓库、作者、短 Hash、提交信息、文件变化与代码增删；各字段按内容开关脱敏或隐藏。
- 图片使用稳定宽度和分页高度，避免因长仓库名或提交信息溢出、遮挡或改变图片结构。
- 不在图片中显示本地路径、作者邮箱、完整 Hash、扫描日志或其他运行环境信息。

## 7. 数据与接口要求

### 7.1 查询接口调整

- `GET /commits/by-date`、`GET /statistics/overview` 仅校验日期合法性与开始/结束顺序，不再校验 2 年或 3 年的跨度。
- 对长范围查询使用数据库聚合返回摘要、按日/按月趋势和分段明细；不得为概览图一次性加载全部 Commit 后在前端聚合。
- 新增数据边界查询接口；返回结果仅包含当前条件的聚合信息。
- 现有 SQLite 索引应覆盖 `commit_date`、`repo_id + commit_date` 与 `author_email + commit_date`。若查询计划未命中索引，应补充迁移与验证。

### 7.2 图片生成

- 图片在浏览器本地生成，不上传图片或提交明细到第三方服务，也不在服务端持久化报告或图片文件。
- 可复用现有单日提交图片生成模块的 SVG 与 Canvas 转 PNG 能力，新增周期概览图与月度明细图布局。
- 汇总图生成仅依赖聚合数据；月度明细图按月请求数据并顺序生成，避免浏览器一次持有全部历史 Commit 和全部图片 Blob。
- 多图导出使用 ZIP，压缩包中仅包含用户确认导出的 PNG 文件。

## 8. 性能与安全要求

1. 长时间范围的首页查询和概览图生成前统计仅传输聚合数据；首次不返回全部明细。
2. 以 10 年、20 个仓库、10 万条已入库 Commit 为基准，概览查询及预览生成 P95 小于 2 秒；单月明细图生成 P95 小于 3 秒。超出该规模时展示明确加载状态和可重试错误。
3. 生成 ZIP 时逐月处理，完成一个月后释放对应图片 Blob，防止浏览器内存持续增长。
4. 导出前必须提示用户检查提交信息是否包含账号、内部地址、客户名或其他敏感内容。
5. 默认脱敏策略必须生效，且关闭某字段后该字段不应存在于 SVG、Canvas 或下载文件中。

## 9. 验收标准

1. 用户可在工作台选择跨度超过 2 年的合法日期并成功查看结果，刷新带 `start`、`end` 的 URL 后范围与结果保持一致。
2. 用户可在数据总览选择跨度超过 3 年的合法日期并成功查看汇总与下钻。
3. “全部历史”准确使用当前筛选条件下已入库提交的最早和最新日期，不以固定年份或当前日期替代。
4. 选择 10 年数据不会自动触发手动同步；手动同步超过 6 个月时需确认，确认后按所选范围执行。
5. 用户可从当前已应用条件打开导出配置、预览概览图并确认下载 PNG；筛选未应用时不可导出。
6. 导出的概览图包含日期范围、数据局限声明、关键指标、趋势和仓库活动分布；超过 18 个月时趋势按月聚合。
7. 默认图片不包含本地路径、作者邮箱、完整 Hash 和提交信息；关闭任意内容项后，下载的图片中不存在该项内容。
8. 选择月度明细后，每个有提交的月份均产出图片；单月超过 100 条提交时按规则拆分，且全部图片被打包下载。
9. 单月图生成失败时，不产出不完整 ZIP，并能重新执行该次导出。
10. 图片生成不创建公开链接、报告持久化记录或服务端图片文件。

## 10. 待确认项

1. 是否需要同时导出 PDF；本期仅提供 PNG 与包含 PNG 的 ZIP。
2. 是否需要在图片中保留具体仓库名和作者名；当前建议默认关闭，仅由用户在导出前开启。
3. 长期数据在 10 万条以上时，是否接受“仅汇总图”优先完成、月度明细分批生成的交互。
