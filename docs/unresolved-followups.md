### 2.1 「为什么没有扫描入库？」（根因未定论）

可能方向（需你本地/环境逐项排除）：

- 统计页是否**手动触发过扫描**，或是否存在**已到期的定时任务**；扫描区间是否覆盖目标日期。
- 该仓库在系统中是否**启用**，路径是否指向当前机器上真实存在的目录。
- **作者过滤**：扫描侧只认仓库配置里的**作者邮箱**；若 Git 提交作者邮箱与配置不一致，会被整段过滤掉（与统计页「按作者筛选」无关）。
- 后端日志 / 扫描状态接口：是否有报错、`git pull` 失败、权限问题等。

**待办**：在你常用的环境里跑一遍「配置核对 + 一次覆盖区间的扫描 + 查库/API」，把结论写回本节或关单。

### 2.2 忽略分支 + 去重 + `branch`（历史问题，已在 v1.3 实现中处理）

**原问题**：查询阶段按忽略分支过滤 `branch`，叠加「先 develop 入库、branch 不升级」，导致已合并提交仍不可见。

**当前实现**（约 2026-03-25 起，见 [requirements.md §2.7.7](./requirements.md)）：

- 扫描改为 **`git log --all`** 单次遍历 + **查询不再按忽略分支过滤**；新入库 `branch` 多为 `null`。
- 若你仍看不到某段日期内的提交，请回到 **§2.1** 排查扫描区间、作者邮箱、路径与是否执行扫描。
