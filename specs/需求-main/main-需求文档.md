# main 需求文档

## 开发分支
`main`

## 背景与目标

`/git-statistics` 的“提交明细”当前采用左侧日期列表和右侧单日时间线的双向滚动工作台。该交互不利于连续浏览多日提交；恢复为单列日期折叠面板，使页面保持一个主要滚动区域，并默认展示最新日期的提交。

“提交活动汇总”当前直接展示精确数值，大规模数据不便快速扫读。汇总卡片改为模糊量级展示，并通过悬浮提示保留精确值查询能力。

## 需求范围
| ID | 需求点 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| R1 | 将提交明细改为单列按日期折叠的列表，不再展示左侧日期导航与右侧独立滚动时间线。 | 桌面端和窄屏均只显示一个日期折叠列表；页面不再产生日期导航与提交明细两个并列滚动区。 | 已验证 |
| R2 | 默认展开结果中的最新日期，并允许用户展开或收起日期面板查看该日提交。 | 首次加载或筛选结果更新后，第一天处于展开状态；日期面板可正常展开/收起。 | 已验证 |
| R3 | 保留日期和提交的关键信息及现有数据语义。 | 日期头继续展示提交数、工作状态、发版和加班信息；展开后按时间从早到晚展示仓库、作者、Hash、时间、分支、提交信息、文件变更、代码增删和加班状态，Hash 可复制。 | 已验证 |
| R8 | “提交活动汇总”的四项指标使用模糊量级展示，悬浮时显示精确值。 | 0 显示为 `0`；1–999 显示为 `<1k`；千级和万级数据分别按一位小数向下取整显示为 `k+`、`w+`，无效小数不保留；悬浮数值时显示带千分位的精确值，新增/删除行数保留 `+`/`-` 语义。 | 已验证 |

## 非目标

- R1–R3 不修改提交查询 API、数据模型、筛选条件、汇总卡片或工作状态计算；R8 仅调整汇总卡片显示格式，不改变统计数据和计算逻辑。
- 不改动 `/data-overview` 已复用的 `CommitsByDateList`。
- 不恢复按仓库 Tab 或新增仓库筛选交互。
- 不将 Redis 作为主数据库，不缓存日志、扫描状态等强实时接口。

## Redis 缓存需求
| ID | 需求点 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| R4 | 为统计、概览、按日提交和分页提交查询增加 Redis 结果缓存。 | 相同规范化查询条件在 TTL 内命中缓存，响应结构与未缓存时一致。 | 已实现 |
| R5 | Redis 连接失败、超时或未启用时自动回源 SQLite。 | 停止 Redis 后查询接口仍返回正确结果，服务不因缓存异常退出。 | 已实现 |
| R6 | 提交写入和指标配置更新后失效相关缓存。 | 新增提交或更新指标后，下一次查询不返回旧统计结果。 | 已实现 |
| R7 | 提供跨设备 Redis 缓存快速配置与使用文档。 | 文档包含 Docker 启动、环境变量、缓存接口、验证和排障步骤。 | 已实现 |
