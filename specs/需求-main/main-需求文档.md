# main 需求文档

## 开发分支
`main`

## 背景与目标

`/git-statistics` 的“提交明细”当前采用左侧日期列表和右侧单日时间线的双向滚动工作台。该交互不利于连续浏览多日提交；恢复为单列日期折叠面板，使页面保持一个主要滚动区域，并默认展示最新日期的提交。

## 需求范围
| ID | 需求点 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| R1 | 将提交明细改为单列按日期折叠的列表，不再展示左侧日期导航与右侧独立滚动时间线。 | 桌面端和窄屏均只显示一个日期折叠列表；页面不再产生日期导航与提交明细两个并列滚动区。 | 已验证 |
| R2 | 默认展开结果中的最新日期，并允许用户展开或收起日期面板查看该日提交。 | 首次加载或筛选结果更新后，第一天处于展开状态；日期面板可正常展开/收起。 | 已验证 |
| R3 | 保留日期和提交的关键信息及现有数据语义。 | 日期头继续展示提交数、工作状态、发版和加班信息；展开后按时间从早到晚展示仓库、作者、Hash、时间、分支、提交信息、文件变更、代码增删和加班状态，Hash 可复制。 | 已验证 |

## 非目标

- 不修改提交查询 API、数据模型、筛选条件、汇总卡片或工作状态计算。
- 不改动 `/data-overview` 已复用的 `CommitsByDateList`。
- 不恢复按仓库 Tab 或新增仓库筛选交互。
